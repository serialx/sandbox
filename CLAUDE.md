# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

The **AIO Sandbox** ("all-in-one" agent sandbox) — a single Docker container that exposes Browser, Shell, File, Code-execution, Jupyter, VS Code, and MCP capabilities to AI agents behind one nginx gateway on `:8080`. This monorepo holds the image build, the multi-language client SDKs, the docs site, an evaluation harness, and runnable examples.

It is a **pnpm + uv polyglot monorepo**. The pnpm workspace (`pnpm-workspace.yaml`) contains only `website` and `sdk/js`; everything else is independent (Python via `uv`/`pip`, Go, or the Docker build context).

| Path | What it is | Toolchain |
|---|---|---|
| `docker/` | The product: reconstructed multi-stage, multi-arch image build (the runtime). Contains the **recovered API server source** under `docker/context/python-server/`. | Docker / BuildKit |
| `sdk/fern/` | Fern config that **generates** all SDKs from the OpenAPI spec. | Fern CLI |
| `sdk/js`, `sdk/python`, `sdk/go` | **Generated** client SDKs (`@agent-infra/sandbox`, `agent-sandbox`, `sandbox-sdk-go`). `sdk/go` output actually targets a sibling repo. | rslib/vitest · setuptools · go |
| `website/` | Docs site (rspress). Also **hosts the OpenAPI spec** Fern consumes. | rspress |
| `evaluation/` | MCP-tool benchmark harness; drives a live sandbox with an LLM. | uv (py ≥3.13) |
| `examples/` | ~14 standalone example projects, each its own `uv` project. | uv (py ≥3.11) |
| `cli/` | **Empty placeholder** (`.gitkeep`). The real `aio` CLI source lives at `docker/context/aio/`. | — |

## The central architecture: OpenAPI is the contract

This is the most important thing to understand before changing the API or any SDK:

```
docker/context/python-server/app   (FastAPI app — the source of truth)
   │  routes annotated with openapi_extra={'x-fern-sdk-group-name', 'x-fern-sdk-method-name'}
   ▼
website/docs/public/v1/openapi.json  (committed OpenAPI spec, generated by FastAPI)
   │  consumed by sdk/fern/generators.yml
   ▼
fern generate  ──►  sdk/python/agent_sandbox  ·  sdk/js/src  ·  ../../sandbox-sdk-go
```

Consequences:
- **Do not hand-edit generated SDK code.** Files under `sdk/js/src` and `sdk/python/agent_sandbox` are overwritten by Fern. The only hand-written code is protected by `.fernignore` in each SDK (notably the `providers/` directories — the Volcengine provider, signing, custom fetchers).
- **To change the API:** edit the FastAPI app in `docker/context/python-server/app`, regenerate `website/docs/public/v1/openapi.json`, then run Fern to propagate to all SDKs, and commit all three.
- Routes are organized as `app/api/v1/<feature>.py` (thin HTTP layer) → `app/services/<feature>.py` (logic) with `app/models/` + `app/schemas/` for types. MCP tools live in `app/mcp/`.

## The docker/ image is a reconstruction

`docker/` began as a faithful **reverse-engineering** of a lost upstream image (`ghcr.io/agent-infra/sandbox`), but has since been **forked and modernized to an `ubuntu:26.04` base** — it **no longer targets byte-parity** with upstream (single uv-managed Python 3.13 + an isolated server venv, `supervisor` from apt, manim/opencv dropped, yt-dlp added). See `docker/README.md` for the full strategy and fidelity notes. Practical implications:
- Components are either installed from pinned upstream sources or **recovered source rebuilt** (`python-server`, `browser-sdk`, the `aio` CLI, the Node REPL servers). The recovered source still mirrors upstream behavior — don't refactor it for style; change it only with intent (the 26.04/3.13 migration is one such deliberate divergence).
- **Runtime orchestration:** PID 1 is `docker/context/rootfs/opt/application/run.sh`, which derives all runtime config from env vars then `exec`s **supervisord** (root, dropping to user `gem`, uid 1000). An **nginx gateway on `:8080`** fronts every service; the FastAPI `python-server` runs on `127.0.0.1:8091`. Supervisord units + nginx configs live under `docker/context/rootfs/opt/gem/`.
- **Auth is opt-in:** nginx only enforces authentication when `SANDBOX_API_KEY` or `SANDBOX_JWT_PUBLIC_KEY` is set (`run.sh`); otherwise the sandbox is fully open by design (it prints a security-risk banner). Port map and env vars are documented in `docker-compose.yaml` and `docker/README.md`.
- See `SECURITY-AUDIT.md` (repo root) before touching the nginx/auth layer — it documents two known upstream-inherited auth-bypass classes in the gateway configs.

## Common commands

### JS / docs (pnpm workspace)
```bash
pnpm install                                   # installs website + sdk/js (CI uses pnpm 9, Node 20; engines: Node >=18)

# SDK (sdk/js)
pnpm --filter @agent-infra/sandbox build       # rslib build && tsc (emits dist/{esm,cjs,types})
pnpm --filter @agent-infra/sandbox test        # vitest (tests in sdk/js/__test__)
# single test: cd sdk/js && pnpm vitest run __test__/<file>.test.ts -t "<name>"

# Docs site (website)
pnpm --filter website dev                       # rspress dev server
pnpm --filter website build                     # rspress build

# Format / lint (Biome at repo root; Prettier also configured)
npx @biomejs/biome check --write .              # lint + organize imports + format (single quotes, space indent)
npx prettier --write .
```

### Regenerate the SDKs (Fern)
```bash
# requires the Fern CLI (npm i -g fern-api). Spec source: website/docs/public/v1/openapi.json
cd sdk/fern
fern generate --group python-sdk --local        # → sdk/python/agent_sandbox
fern generate --group js-sdk --local            # → sdk/js/src
fern generate --group sdk-go --local            # → ../../sandbox-sdk-go (sibling repo)
```

### Python SDK (sdk/python — generated)
```bash
cd sdk/python
python -m build         # setuptools (package: agent-sandbox, import: agent_sandbox)
./publish.sh            # build + twine upload
```

### Build & run the image (docker/)
```bash
# build context root is the docker/ directory
docker build -t aio-sandbox -f docker/Dockerfile docker/
docker run --rm -p 8080:8080 --shm-size=2g --security-opt seccomp=unconfined aio-sandbox
# or: docker compose up   (edit image: in docker-compose.yaml to your local tag)
# then open http://localhost:8080  (API docs at /v1/docs)
```

### Evaluation harness (evaluation/)
```bash
cd evaluation
cp .env.example .env        # set LLM creds (Azure OpenAI by default, or OpenAI-compatible)
uv run main.py              # all categories; --eval <basic|browser|...> for one; --agent openai --openai-model ...
# requires a running sandbox reachable at http://localhost:8080/mcp
```

### Examples (examples/)
```bash
cd examples/<name>          # e.g. basic-file-operations, openai-integration
uv run main.py              # each depends on the local agent-sandbox SDK + a running sandbox at :8080
# to add one: copy examples/_template/ and edit main.py
```

## Conventions & gotchas

- **Generated vs. hand-written SDK code** — see the OpenAPI section above. Edits outside `.fernignore` paths will be lost on the next `fern generate`.
- **`cli/` is empty.** Don't look for the `aio` CLI there; its source is `docker/context/aio/` (re-authored into a buildable npm package; the image's `aio-build` stage bundles it with esbuild).
- **`CONTRIBUTING.md` is partly stale** — it references `sdk/javascript/` and per-SDK `cd` workflows that don't match the actual `sdk/js` + pnpm-workspace layout. Trust this file and the package manifests over it.
- **Two package managers:** JS uses **pnpm** (only `website` + `sdk/js` are in the workspace); Python uses **uv** (`evaluation`, `examples/*`, and `sdk/python` all have `uv.lock`/pyproject).
- **CI** (`.github/workflows/`): `sdk-ci.yml` builds + tests `sdk/js` on changes to `sdk/js`/`sdk/fern`; `sdk-publish.yml` publishes SDKs; `docker-release.yml` builds the image from `docker/Dockerfile` and pushes a multi-arch (amd64 + arm64) manifest to GHCR **on `v*` tags only** — each arch builds natively (amd64 on `ubuntu-latest`, arm64 on `ubuntu-24.04-arm`), pushes by digest, then a merge job stitches them into one manifest tagged `X.Y.Z`/`X.Y`/`X`/`latest`. (This fork builds its own image from this Dockerfile; it no longer just mirrors the upstream prebuilt image.)
